Review 2 of vm_process.py (Claude, 2026-10-13). Fix exactly these points, keep everything else.

1. `VmProcess.wait()`: a wait that is ALREADY BLOCKED in another thread must return the abandon code as soon as `terminate()` or `kill()` is called. Today it blocks on `self._done_event.wait(...)` until the VM run ends. Add a second `threading.Event` (for example `self._wake`) that is set when the run ends AND in `terminate()` and `kill()` (after the lock is released), and let `wait()` wait on that event; when it returns (or times out) read the state under the lock again: abandoned -> the abandon code, finished -> the exit code, else raise TimeoutError.
2. `make_spawn`: the slot must be released exactly when the VM run (the thread of the VmProcess) has ended. The helper thread `_wait_and_decrement` calls `proc.wait()`, which returns AT ONCE for an abandoned process, so a process abandoned right after the spawn frees its slot while the VM run is still going. Remove the helper thread. Instead wrap `run`: `def tracked(argv): try: return run(argv)` / `finally:` decrement the count (under the lock). Create the process with `VmProcess(tracked, argv)`.
3. `make_spawn`: the count is increased before `VmProcess(...)` is created; if creating the process raises, the count stays too high. Wrap the creation in `try/except BaseException`, decrement and re-raise.
